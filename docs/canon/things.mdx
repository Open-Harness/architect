## The idea

A thing is a noun your system keeps: a sign-up sheet, a person, a draft. It has an id and a set of named fields, and it
lives in a store (which store, and who may write it, is [data](data.mdx)). Each field is made of a value, a named type
such as `Count` or `Title`, declared once and used everywhere. Every value and every field also says who may see it:
its visibility. It is public unless you mark it secret, or private to some roles. One rule decides what a reader sees:
**the declaration's mark is the only thing that decides who sees a field, and every output Orthograph makes reads that
one mark.** The model, the docs, the journal, a span and the MCP door all read it, and nothing downstream can widen it.
Three doors don't yet narrow a private field as MCP does: see the note `private-over-http`.

## The smallest example

The sign-up sheet is a thing. It has an id, a title, and two counts:

```ts file=examples/signup/blueprint/things/sheet/thing.ts name=Sheet lines=4-7
export const Sheet = Blueprint.thing({
  description: "A sign-up sheet with a fixed number of places.",
  fields: { id: Blueprint.id("sht"), title: Title, places: Count, taken: Count },
});
```

`Count` and `Title` are values, named once in `examples/signup/blueprint/values/counts.ts`:

```ts file=examples/signup/blueprint/values/counts.ts name=Count,Title lines=3-6
/** How many of something. */
export const Count = Blueprint.value(Blueprint.uint(32));
/** A short name a person types. */
export const Title = Blueprint.value(Blueprint.text({ max: 120 }));
```

The compiled model is rendered here, not copied. Every field says its value, and the name of that value:

<Model project="examples/signup" thing="sheet" show="fields" />

None of the sheet's fields is marked, so all of them are public. A sign-up sheet has nothing to hide, so secret and
private are shown with acme, whose starter signs people in with a password. In acme, a password and a bearer token are
values marked secret, once:

```ts file=examples/acme/blueprint/values/identity.ts name=Password,Secret lines=3-6
/** What a person signs in with. Never stored by the project: Better Auth keeps only its hash. Secret: never in telemetry. */
export const Password = Blueprint.visibility.secret(Blueprint.text({ max: 128 }));
/** A secret shown once: a session's bearer token, or an API key. Secret: never in telemetry. */
export const Secret = Blueprint.visibility.secret(Blueprint.text({ max: 512 }));
```

## How it works

### A value is a named type

A value is a schema with a name and a visibility. Orthograph gives you a maker for each common shape, and `Blueprint.value` names
anything else, such as an Effect `Schema.Literals`:

```ts file=packages/orthograph/src/modules/values/types.ts name=ValuesApi lines=60-92
export interface ValuesApi {
  /** Name a type: `export const Amount = Blueprint.value(Blueprint.uint(128))`. */
  readonly value: <S extends Schema.Constraint>(schema: S | Value<S>) => Value<S>;
  /** An identifier with a short prefix, such as `alw_7f3k`. Ids of different things never mix. */
  readonly id: <const P extends string>(prefix: P) => Value<Schema.brand<Schema.String, P>>;
  /** A whole number below 2^bits. In code a `bigint`; on the wire a decimal string, since JSON numbers lose precision. */
  readonly uint: (bits: number) => Value<Schema.BigIntFromString>;
  /** Text, never empty, at most `max` characters (default 200). */
  readonly text: (options?: { readonly max?: number }) => Value<Schema.String>;
  /** A moment: stored as a UTC instant, written on the wire, in answers, events and reads as ISO 8601 with milliseconds (`"2027-01-10T09:00:00.000Z"`). A move made by time anchors on a field of this type (M8-checks, call 1). */
  readonly instant: () => Value<Schema.String>;
  /** A reference carrying a thing’s declaration name and the id of one instance. */
  readonly refAny: () => Value<Schema.Struct<{ readonly declaration: Schema.String; readonly id: Schema.String }>>;
  /**
   * Say what a value or a thing's field is for: `title: Blueprint.described(Blueprint.text({ max: 120 }), "The words a link shows.")`.
   * Gives back the same kind, so it goes wherever the original went; a field made from it keeps the sentence.
   */
  readonly described: <const X extends Value | Field>(x: X, description: string) => X;
  /** An account on a chain, as CAIP-10 text (`eip155:31337:0x…`); an `address` in Solidity. */
  readonly account: () => Value<Schema.String>;
  /** An amount that names its asset (M6-money). */
  readonly money: MoneyApi;
  /** An email address: text of at most 254 characters, with an `@` and a dot after it. */
  readonly email: () => Value<Schema.String>;
  /** True or false. */
  readonly bool: () => Value<Schema.Boolean>;
  /** One of the words named: `Blueprint.oneOf(["observing", "live"])`. */
  readonly oneOf: <const O extends ReadonlyArray<string>>(options: O) => Value<Schema.Literals<O>>;
  /** Many of one value: a list, written as an array. */
  readonly list: <S extends Schema.Constraint>(item: Value<S>) => Value<Schema.$Array<S>>;
  /** A field the record may lack: absent from a payload, an event or a row until it is set. */
  readonly optional: <S extends Schema.Constraint>(value: Value<S>) => Value<Schema.optionalKey<S>>;
}
```

Values are named for three reasons:

- **One meaning everywhere.** The model records each field's value and its name (`named: "Count"`). So every output
  reads the same type: a `bigint` in Effect, a decimal string on the wire. `places` and `taken` are both a `Count`, so
  they can never drift apart, and changing `Count` once changes both. A value's type on a chain is worked out from the value, not
  written by hand (K25 item 5: `uint(bits)` is `uint<bits>`, `account()` is `address`; ledger `THI-01`, built in M6.10).
- **One mark everywhere.** Visibility rides on the value. acme's `Password` is marked secret once, and every payload
  field made of it, in `sign-up` and `sign-in`, is secret with no further word.
- **A name a reader can say.** `places: Count` says what the field is. `places: Blueprint.uint(32)` only says how big
  it is.

There is no value for a time, a yes-or-no or a list of choices yet. That is one reason the sheet has no closing date.

### An id is a value with a prefix

`Blueprint.id("sht")` makes text that starts with `sht_` and is branded as a sheet's id. Ids of different things never
mix: a field that takes an organisation's id takes `org_1` and refuses `alw_1`
(`packages/orthograph/src/modules/things/things.test.ts:24`). A new id is the prefix and random base-36, and the random
comes from Effect, so a test world can seed it (`packages/language-effect/src/modules/ids/types.ts:1`). Every thing
must have a field called `id`: the type of `Blueprint.thing` asks for one
(`packages/orthograph/src/modules/things/types.ts:35`). The sheet's handler for `open` makes one:

```ts file=examples/signup/src/sheet/open.ts name=open lines=11-12
const sheet = yield* Ids.of(Sheet.fields.id);
yield* steps.insert(records.insert(Sheet, { id: sheet, title, places, taken: 0n }));
```

### A field is a value in a place

A field is a value that belongs to a thing, under a key. It knows its thing, its key and what it was made from:

```ts file=packages/orthograph/src/modules/things/types.ts name=Field lines=6-25
/** A field of one thing, which another thing or a payload can reuse: `Organization.fields.id`. */
export interface Field<V extends Value = Value, K extends string = string, F extends FieldsInput = FieldsInput> {
  readonly kind: "field";
  readonly of: Thing;
  /** The field's own key; its type too, so a rule can tell `name` from `owner` (G5). */
  readonly key: K;
  /** Type only, never present: the thing's fields, so a rule can tell one thing's field from another's (G5). */
  readonly "~thing"?: F;
  readonly value: V;
  /** The field it was taken from, when declared as another thing's field: the model's edge. */
  readonly from: Field | undefined;
  /** Who may see this field's value: its own mark, or that of the value or field it was made from. */
  readonly visibility: Visibility;
  /** What the field is for, in a sentence a caller reads: its own, or that of the value or field it was made from (M1.42). */
  readonly description?: string;
  /** Explicit opt-in to tracing a public text field, inherited from its declaration. */
  readonly traced?: true;
  /** A secret answer field handed to its caller once (`Blueprint.issued`); the compiler refuses it on a thing's own field. */
  readonly issued?: true;
}
```

You declare a field as a value (`places: Count`), or as another thing's field. Payloads and answers are made of fields
too, so `sheet.join` takes `Sheet.fields.id` and gets the same id type the thing has:

```ts file=examples/signup/blueprint/things/sheet/verbs/join.ts name=default lines=9-10
payload: { sheet: Sheet.fields.id, people: Count },
answer: { left: Count },
```

A thing's field taken from another thing is an edge: the model records `ref`, and the field takes that field's type
and visibility. The sheet stands alone, so acme shows one: its allowance's `organization: Organization.fields.id`
records `ref: "organization.id"`.

A thing has two more parts. `lives` says which store it lives in. Leave it out, as the sheet does, and it lives in
the project's default store: the model above says `"lives": "database"`. What a store is, and the other places data
lives, is [data](data.mdx). Today the code takes a closed list, `"database"` or `"actor"`
(`packages/orthograph/src/modules/things/types.ts:32`); K3 makes store kinds open, built in M1.17. And `code` is the prefix
of the thing's refusal codes, `SH` in `SH-001`. When it is unset the compiler takes two letters of the name.

### A name comes from a path

You never write a thing's name. The folder `blueprint/things/sheet/` names it `sheet`, and the compiler gives it the
identifier `Sheet`. A value is named by its export, so `export const Count` is `Count` in the model. The prefix you
pass to `Blueprint.id` is part of the value, not a name. How the folders map to names, and why a name is never written
as a string, is on [blueprint](blueprint.mdx).

### Who may see a field

There are three visibilities. Public is the default:

```ts file=packages/orthograph/src/modules/visibility/types.ts name=Visibility,VisibilityApi lines=14-39
/** `public`; `secret` (a password, token, key or session: nobody's, recorded nowhere); or private to some roles. */
export type Visibility = "public" | "secret" | PrivateTo;

export interface VisibilityApi {
  /** Allow a public text value or field to appear in traces. Preserves its visibility and schema. */
  readonly traced: <const X extends Value | Field>(x: X) => X;
  readonly visibility: {
    /**
     * Mark a value, or one field of a thing, as secret: `Blueprint.visibility.secret(Blueprint.text({ max: 128 }))`.
     * Gives back the same kind, so it goes wherever the original went.
     */
    readonly secret: <const X extends Value | Field>(x: X) => X;
    /** Private to a list of roles: `Blueprint.visibility.private(Balance, admin)`. */
    readonly private: <const X extends Value | Field>(x: X, ...roles: readonly [Role<any>, ...Array<Role<any>>]) => X;
    /** Public again: the default, said out loud. */
    readonly public: <const X extends Value | Field>(x: X) => X;
  };
  /**
   * Mark a secret answer value as handed to its caller once: `answer: { token: Blueprint.issued(Token) }`, where `Token`
   * is a secret value or a secret field. The answer of the call that issued it carries it, to that call's own caller, over
   * HTTP, the SDK and the CLI; it never leaves in a refusal, a read, MCP, telemetry, the journal or a generated file.
   * Gives back the same kind, so it goes wherever the original went. It is only a mark: the compiler refuses it on
   * anything but a secret value in an operation's answer.
   */
  readonly issued: <const X extends Value | Field>(x: X) => X;
}
```

- **public**: anyone the operation answers may see it. This is the default. A public text field needs a separate mark
  to appear in telemetry.
- **secret**: a password, a token, a key. It goes to the caller who asked for it and nowhere else.
- **private to roles**: a value only some roles may see, such as a balance an admin may read.

A mark gives back a copy of the same kind, so a marked value goes wherever the original went. You can mark a value,
as `Password` is, or one use of a field. acme's `sign-in` answers the session's own id, marked secret for this one
answer, without touching the session thing's field:

```ts file=examples/acme/blueprint/things/session/verbs/sign-in.ts name=default lines=9-11
payload: { email: Person.fields.email, password: Password },
// The caller is handed both once, in this answer: `issued` lets a secret leave there and nowhere else.
answer: { session: Blueprint.issued(Blueprint.visibility.secret(Session.fields.id)), token: Blueprint.issued(Secret) },
```

No example has a private field yet. This is the test that proves the mark, with a role made for it:

```ts file=packages/orthograph/src/modules/visibility/visibility.test.ts name=visibility lines=41-47
it("is private to a list of roles", () => {
  const t = Things.thing({ description: "x", fields: { id: Values.id("x") } });
  const admin = Roles.role(t, { rule: () => true });
  const balance = visibility.private(Values.uint(128), admin);
  expect(balance.visibility).toEqual({ kind: "private", to: [admin] });
  expect(visibility.public(balance).visibility).toBe("public");
});
```

### What each visibility changes

This is what each mark does today, place by place:

| Where | public | secret | private to roles |
|---|---|---|---|
| The answer over the HTTP API, the SDK and the CLI | sent | sent to the caller who asked (how a token is handed over) | sent to every allowed caller (see the note `private-over-http`) |
| The answer and refusals over MCP | shown | never shown | shown only to a caller who holds one of the roles in this call |
| A payload field over MCP | offered | never offered; naming it anyway is refused as `InvalidPayload` | never offered |
| An event in the journal | written | left out | left out |
| A span attribute | written (free text until M1.19) | never | never |
| The model | nothing written: public is the default | `"secret"` | the role names, as `thing.role` |
| The generated docs | the field's type | the type, then "(secret)" | the type, then "(private to" and the roles |
| An eval on live traffic | checked | not checked | not checked |

Where each row is decided:

- **The answer over MCP** goes through the one visibility rule, for the agent audience
  (`packages/language-effect/src/modules/visibility/internal/rule.ts:10`). The roles the caller holds are asked only when
  some field is private, the way the role check decides them (D3 #125). A field the declaration doesn't name is never
  shown. This is why acme's `session.sign-in` can't be called through MCP: a password never passes through an agent.
  Every door and what it reaches is [doors](doors.mdx).
- **The journal** keeps only an event's public fields
  (`packages/language-effect/src/modules/handler/internal/move.ts:70`, through
  `packages/language-effect/src/modules/handler/internal/attributes.ts:39`). The journal is a record anyone who
  reads it can see. So a journey can check a secret field of an event only through the answer, never through the
  event. How events reach the journal is [machines](machines.mdx).
- **Spans** take `payload.<field>` and `answer.<field>` from declared public fields. Public text needs
  `Blueprint.traced(...)` (`packages/language-effect/src/modules/handler/internal/attributes.ts:10`). `ortho prove`
  checks spans and logs for secret, private and untraced text values. What a span says is [traces](traces.mdx).
- **The model** leaves public out, writes `"secret"`, or names the roles. A private field whose role isn't exported
  from a `roles.ts` is a problem `ortho check` reports
  (`packages/compiler/src/modules/model/internal/describe.ts:29`).

The sheet's public `title` stays in answers and events. Its `Blueprint.text()` declaration keeps it out of the
operation's span. A short code you search by can opt in with `Blueprint.traced(...)`:

```ts planned=M1.19 path=blueprint/values/codes.ts
export const Ref = Blueprint.traced(Blueprint.value(Blueprint.text({ max: 12 })));
```

## Choices

### Which visibility

| | public | secret | private to roles |
|---|---|---|---|
| Use it for | ids, counts, states, names you search by | passwords, tokens, keys, a session handed over once | a value some roles may read and others may not |
| You can find it in a trace | yes, with `Blueprint.traced` required for free text | no | no |
| It is in the event, so a view or a journey's `emits` can read it | yes | no | no |
| An agent can send it or read it over MCP | yes | no | only an agent acting for someone who holds the role |

Pick public by default. Mark a value secret when nobody but the caller who asked should ever see it, anywhere. Mark it
private when the question is who, not whether. A private field costs you the trace and the event, so a field you
need to debug by should stay public.

### Mark the value, or one field

Mark the value when every use is sensitive: a `Password` is secret wherever it goes. Mark one field when the same
value is public in one place and sensitive in another: a session id is public on the session, and secret in the
answer that hands it over.

### A value, or another thing's field

Declare a field as another thing's field when it points at that thing, such as acme's `member: Person.fields.id`. You
get the same id type, the visibility that field has, and an edge in the model. Declare it as a value when it is the
thing's own fact: `places: Count`.

### Where it lives

Leave `lives` out, and the thing lives in the project's default store. Choosing a store, and what each kind can do,
is [data](data.mdx), and in depth [stores](stores.mdx).

## What it is not

- **Not a table.** A thing is what the system keeps, not how. A store holds its tables, and a thing that lives as an
  actor has none. See [stores](stores.mdx).
- **Not its state.** A sheet's state, `open` or `full`, is not a field you write. Its machine owns it and moves it.
  See [machines](machines.mdx).
- **Not a secret in the `secrets` sense.** A secret field is the user's data, such as a password a person types. A
  value in `secrets` is the project's own, such as Stripe's key, named by the description and never held by it.
- **Not a role.** Private visibility names roles, but who may call an operation at all is [roles](roles.mdx).
- **Not a list.** A thing is one instance. A list across things, or across stores, is a view: see [views](views.mdx).

## Notes

<Note kind="decision" decision="N1">
  Visibility on fields, events, arguments and refusals, public by default, carried into the model; telemetry through
  an allowlist built from it. Decision 3 of N1, built as layer 2's L2.P.
</Note>

<Note kind="decision" decision="D3">
  Redaction by role (#125): over MCP only public fields are in a tool's input and answer, and a private field is shown
  only to a caller who holds one of its roles in this call.
</Note>

<Note kind="decision" decision="O2">
  Gap 2: free text is not traced unless it is marked. Ids, amounts, enums, booleans and times stay traced when public.
</Note>

<Note kind="decision" decision="K3">
  A thing lives in a store, and store kinds are an open list (item 2). The word "home" is retired (ledger `G-03`); a
  thing's `lives` is owned by [data](data.mdx).
</Note>

<Note kind="question" id="private-over-http">
  Ledger `OPS-01`. Should the HTTP API, the SDK and the CLI redact a private field the way MCP does? Today they send
  every declared field to any caller the operation allows, and D3 #125 says so: "the redaction is MCP's". No example's
  field is private, so nothing shows the gap yet. K5 puts each operation's enforcer in one place, the wrapper on the
  Worker, and every door reaches it ([doors](doors.mdx)). That is where a private field would have to be redacted for
  "private to roles" to mean the same in every door. No slice owns it yet.
</Note>

<Note kind="question" id="secret-at-rest">
  What does secret mean for a thing's own field, at rest? The mark keeps it out of telemetry, the journal and MCP. But
  the store keeps every field as it came: D1 gets a `TEXT` column for each one
  (`packages/projections/src/modules/server/internal/worker-config.ts:62`). acme avoids this by never storing its
  secrets (Better Auth keeps only a hash). Nothing refuses, hashes or encrypts a secret field on a thing. No ledger
  row or slice owns it yet.
</Note>

<Note kind="question" id="value-visibility-in-model" slice="M1.03">
  The model's `values` list leaves visibility out: `Password` and `Secret` read as plain `text`
  (`packages/compiler/src/modules/model/internal/describe.ts:159`). Visibility is written only on the fields made of
  them. A generator reading the values alone would treat a password as public.
</Note>

<Note kind="question" id="visibility-on-a-store" slice="M1.17">
  What each visibility means in each kind of store is open, above all for private state on a chain (ledger `G-04`).
  K7 and K25 decided the chain kinds: a public chain store refuses a secret or private field, and Aztec's `private` is a
  capability of its own kind (ledger `G-04`). That question belongs to [stores](stores.mdx), as its note `visibility-per-kind`.
</Note>

<Note kind="question" id="lives-closed-list" slice="M1.17">
  Ledger `X-17` and `STO-26`. A thing's store is still a closed list in code: `"database"` or `"actor"`
  (`packages/orthograph/src/modules/things/types.ts:32`, and again in `packages/compiler/src/modules/model/types.ts:41`).
  K3 says a thing lives in a store of an open kind, and K5 makes a chain a host whose store kind is `chain`. What a
  thing declares to live on a chain is K25's: it lives in a chain store, a file saying `Blueprint.store.chain.evm()`, built in
  M6.10. The change is in [stores](stores.mdx).
</Note>

<Note kind="question" id="file-as-field">
  K3 says R2 holds files, "which are fields", and [stores](stores.mdx) sends a reader here for them. No value for a
  file exists, and no slice builds one. Until one does, a file is not a field.
</Note>

<Note kind="question" id="target-word">
  Ledger `G-02`. The retired word "target" still means language in two comments the page leans on:
  `packages/orthograph/src/modules/values/types.ts:8` ("readable by every target") and
  `packages/orthograph/src/modules/visibility/types.ts:2` ("A target that has no private state"). It is due to be renamed
  to language.
</Note>
