## The idea

Two words, two jobs. A **language** is what behaviour is written in, and what the model is rendered into. It owns the
frame a handler fits, the blanks, what the enforcer means, and the clients written in it. A **host** is where code
runs. It supplies what the runtime needs in that place: a database, a clock, somewhere to send spans. One rule keeps
them apart: **a language never chooses where it runs, and a host never gives an operation meaning.** An operation's
**`runs`** says which place it runs in. Today there is one answer, the server, and Orthograph has one language and one
host that serve it: Effect, on Cloudflare.

## The smallest example

The sign-up sheet's generated Worker is where the two meet. Everything that gives a call its meaning comes from the
language, `language-effect`. Everything that is about the place comes from the host, `host-cloudflare`:

```ts file=examples/signup/generated/server/main.ts name=imports lines=9-10
import { AuthD1, Database, JournalD1, StoreD1, Telemetry, toWorld } from "@orthograph/host-cloudflare";
import { Auth, Busy, BusyLive, CallTelemetry, Environment, Handlers, Journal, Principals, Reads, Store, Wire, thingIn } from "@orthograph/language-effect";
```

`Handlers.serve` is the language's enforcer. It wraps each handler in the same fixed order, whatever host it runs on:

```ts file=examples/signup/generated/server/main.ts name=sheetCloseServed,sheetOpenServed lines=26-29
const sheetCloseServed = Handlers.serve({ name: "sheet.close", operation: sheetClose.declaration, handler: sheetCloseHandler, notFrom: "SheetNotOpen", notFound: { sheet: "SheetNotFound" }, codes: Errors.codes });
const sheetGetServed = Reads.serve({ name: "sheet.get", read: sheetGet.declaration });
const sheetJoinServed = Handlers.serve({ name: "sheet.join", operation: sheetJoin.declaration, handler: sheetJoinHandler, notFrom: "SheetNotOpen", notFound: { sheet: "SheetNotFound" }, codes: Errors.codes });
const sheetOpenServed = Handlers.serve({ name: "sheet.open", operation: sheetOpen.declaration, handler: sheetOpenHandler, codes: Errors.codes });
```

And the handler someone wrote is in the language, with nothing of the host in it. It never names D1, a Worker or a
binding:

```ts file=examples/signup/src/sheet/close.ts name=imports,default lines=1-12
// Scaffolded from blueprint/things/sheet/verbs/close.ts. Yours from now on.
import { Effect } from "effect";
import type { Handler } from "../../generated/api/src/sheet/close.handler.ts";

/** Take a sheet down. Nobody can join it after this. The machine's check already passed. */
const close: Handler = (_payload, { steps, move }) =>
  Effect.gen(function* () {
    yield* steps.record(move("closed"));
    return {};
  });

export default close;
```

The compiled model records the operation's place, `runs: "server"`, the only one accepted today:

## How it works

1. **The language renders the model.** `language-effect` gives each operation its frame (the generated `Handler`
   type) and its enforcer, `Handlers.serve` (`packages/language-effect/src/modules/handler/service.ts:26`). The
   enforcer decodes, checks the role, opens the span, replays a request key, checks the machine, runs the handler and
   commits ([doors](doors.mdx) owns what that means for callers).
2. **The language names what it needs from a host, as services.** The store is one of them. The language declares the
   port and says what a store must do; it never says how:

```ts file=packages/language-effect/src/modules/records/types.ts name=Store lines=67-78
/** The host's side. A failing store dies: it is never the caller's refusal. */
export class Store extends Context.Service<Store, {
  /** The rules this store enforces at commit (G5), as the model carries them; a unit made over it looks through the same ones. Absent when the project declares none. */
  readonly rules?: ReadonlyArray<NamedRule>;
  readonly find: (thing: Thing, id: string) => Effect.Effect<Stored | undefined>;
  /** One page of a thing's instances, in the order they were made (never a clock). A thing that lives as actors has none to list. */
  readonly list: (query: ListQuery) => Effect.Effect<Listed>;
  /** `conflict` too when another call committed the same request key first: the retry then finds its answer. */
  readonly commit: (commit: Commit) => Effect.Effect<Committed>;
  /** The answer already committed under a request key, as wire JSON, if there is one. */
  readonly answered: (key: string) => Effect.Effect<string | undefined>;
}>()("@orthograph/language-effect/Store") {}
```

3. **The host supplies each service for its place.** `host-cloudflare` implements the store over D1
   (`packages/host-cloudflare/src/modules/store/service.ts:11`), and the journal, telemetry and the world the same
   way. The Worker's config is the host's too: a D1 binding and a Durable Object for the world
   (`examples/signup/generated/server/wrangler.jsonc:8-11`).
4. **`runs` says where an operation runs.** The declaration can say three places. Only one is accepted:

```ts file=packages/orthograph/src/modules/operations/types.ts name=Runs lines=32-33
/** Where an operation runs: `server` (every target today), on the caller's `client`, or on a `chain`. */
export type Runs = "client" | "server" | "chain";
```

   The compiler refuses the other two, and says what a project would need to run them:

```ts file=packages/compiler/src/modules/model/internal/describe.ts name=describe lines=177-178
const onDevice = op.runs === "client" && (layout.things.get(thing)?.from.kind ?? "app") !== "app"; // a plugin's, with its code for each host
if (op.runs !== "server" && !onDevice) problems.push(`${file}: runs "${op.runs}" is not supported yet: ${RUNS_NEEDS[op.runs] ?? "an unknown place"}`); else if (onDevice) problems.push(...deviceProblems(file, op));
```

```ts file=packages/compiler/src/modules/model/internal/device.ts name=RUNS_NEEDS lines=5-9
/** What an operation that doesn't run on the server needs: a language that does. Only the Effect language exists today. */
export const RUNS_NEEDS: Readonly<Record<string, string>> = {
  client: "an operation runs on the caller's own device only when a mounted plugin supplies it, with a code entry for each of node, browser and world; this app's own operations all run on the server",
  chain: "it needs a language that runs operations on a chain (language-solidity, or language-noir on Aztec), and this project's only language, language-effect, runs them all on the server",
};
```

### Every language and host

K5 names them all:

```md file=design/decisions/K5-the-whole-shape.md lines=511-524
**A language** is what behaviour is written in and what the model is rendered into. It owns the frame, the blanks,
the enforcer's meaning and the clients written in it:
- `language-effect`: the wrapper and the TypeScript SDK;
- `language-solidity`: the contract, the ABI and the contract's client;
- `language-noir`: later;
- `language-python`: clients only.

**A host** is where code runs, and it supplies what the runtime needs there:
- `host-cloudflare`: workerd, D1, Durable Objects, alarms, OTLP;
- `Host.chain`: an EVM, running the `chain` store kind;
- `Host.node`: the CLI, and adapters workerd can't reach;
- `Host.browser`: client operations and the wallet adapter.

A language never chooses where it runs, and a host never gives an operation meaning.
```

Only the first of each is built. `language-solidity` is a placeholder today:

```ts file=packages/language-solidity/src/index.ts name=file lines=1-2
// @orthograph/language-solidity: the Solidity target.
export {};
```

### Where a chain fits

A chain is a host, `Host.chain`, and `chain` is the store kind that runs on it. The host supplies the kind, and
`language-solidity` writes the code that lives in it (K3 item 2, K27 item 5). That much is decided.
K7, the chain languages worked out together (Aaron, 18 November 2026), decided the rest. Each declared operation is
exactly one generated entry on the chain (on Aztec, a pair). The generated clients may reach every external function the
generated `surface.json` lists, the developer's own included, with a role modifier the scaffold supplies. Solidity is
built first; Solana and Aztec are designed on the same port and built later. [chains-and-wallets](chains-and-wallets.mdx)
has the whole of it, with what is built and what is not.

## Choices

**Which language does an operation's behaviour go in?** Today, Effect, always: it is the only language that runs an
operation. A chain or client language becomes a choice when M6 builds the one K7 designed.

**Which host runs it?** You don't choose per operation. An environment picks the host's place (this machine, or
Cloudflare), and the language's enforcer runs there unchanged:

```ts file=examples/signup/blueprint/environments/local.ts name=default lines=3-8
export default Blueprint.environment({
  runs: "on this machine",
  identity: Identity.testPrincipals, // fixed test people, no sign-in
  database: Cloud.d1.local(), // the local runtime emulates D1: no database process
  telemetry: [Telemetry.sink.local()], // prove's Collector, a process of its own
});
```

**What do I write by hand?** Only the handler, in the language. A host's types never appear in it (K5, "The
boundaries": "a host's types in a handler" never crosses from host to language).

## What it is not

- **Not a projection.** A projection is what the model becomes: the SDK, the CLI, the docs
  ([projections](projections.mdx)). The TypeScript SDK is written in a language, but the SDK projection makes it.
- **Not an environment.** An environment says which place this revision runs in, and binds stores and secrets there
  ([environments](environments.mdx)). An environment's own `runs:` is a sentence describing that place, not an
  operation's `runs` (see the note `two-runs`).
- **Not a store kind.** A host or a language supplies store kinds, such as `database` and `actor` from
  `host-cloudflare` ([data](data.mdx), [stores](stores.mdx)).
- **Not a door.** Where an operation is enforced is the language's; how a caller reaches it is the door's
  ([doors](doors.mdx)).
- **Not a "target".** That word is retired for language (K2, Aaron's call 2).

## Notes

<Note kind="decision" decision="K2">"Target" is renamed language (Aaron's call 2). Effect, Solidity, Noir and Python
are languages; Cloudflare and a chain are hosts.</Note>

<Note kind="decision" decision="K3">A chain is a host (`Host.chain`), and `chain` is the store kind that runs on it,
supplied by the host and written for by `language-solidity` (K3 item 2, K5 decision 8, K27 item 5). This answers
ledger `LAH-04`.</Note>

<Note kind="status" slice="M6.01">K7 decided the chain languages: how an operation maps to a contract's ABI, what clients
may reach, and how Solidity, Noir and Solana share one model. M6.01 starts from K7. Until M6.11 builds it,
`language-solidity` stays a placeholder (ledger `LAH-35`) and `runs: "chain"` is refused (ledger `LAH-19`).</Note>

<Note kind="status" slice="M1.27">An operation that runs on the caller's device (`runs: "client"`, such as a wallet's `send`)
is accepted when a mounted plugin supplies a code entry for `node`, `browser` and `world` (K7, M1.27); an app's own operations
all run on the server. The wallet is the first ([chains-and-wallets](chains-and-wallets.mdx)). Ledger `LAH-02`.</Note>

<Note kind="question" id="target-word">The compiler's refusal now says "needs a language" (`describe.ts:167-170`), but
the retired word is still in the declaration's own comments (`packages/orthograph/src/modules/operations/types.ts:15-16`,
`:21`, `:49`). No slice owns the rest of the rename. Ledger `G-02`.</Note>

<Note kind="question" id="host-service" slice="M1.09">The build plan says the Effect runtime is host-neutral behind a
`Host` service, so a Node host is a fallback if workerd bites. No such service exists in `language-effect`: the host
is chosen by which package the generated Worker imports. Ledger `LAH-27`.</Note>

<Note kind="question" id="two-runs">Two things are called `runs`. An operation's `runs` is a place (`server`, `client`,
`chain`); an environment's `runs:` is a sentence about where the environment is ("on this machine"). One of them
should be renamed before the reference pages are generated. Ledger: LAH-46.</Note>
