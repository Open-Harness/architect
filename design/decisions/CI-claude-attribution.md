# CI-claude-attribution: a Claude Code cloud session leaves the model out, and its footer blocks nothing

26 November 2026. Goal 18's lead. It amends K33 items 4 and 15 for one harness, and changes nothing for the others.

## Evidence

- **K33 makes the model data on the work:** the template's "Harness and model" line and every comment's first line,
  `[goal-<n> · <role> · <harness> · <model>]` (`K33-github-native.md`, items 4 and 15).
- **A Claude Code cloud session may not write it.** It is told never to write a model identifier in anything it
  pushes: pull request titles and bodies, docs and code.
- **Its GitHub connection appends a footer** (`_Generated by Claude Code_`) to every pull request body and comment it
  writes, even a PATCH that sends none. The features lead saw this twice on #1157.
- **Reviewers blocked on both** on 26 November: #1087, #1116, #1153, #1157, #1175 and #1176. Each block cost a push and a
  CI run for nothing the session could change.

## Decision

1. **A Claude Code cloud session leaves the model id out:** its comment lines read `[goal-16 · lead · claude]`, its
   "Harness and model" line reads `claude`, and its brief's front matter has no `lead.model`. The template's line now reads
   `<claude | amp | codex | opencode>[, <model id>]`.
2. **What its environment adds is not an attribution line it wrote:** the `_Generated by Claude Code_` footer on pull
   request bodies and comments, and the `Co-Authored-By` and `Claude-Session` commit trailers. A reviewer blocks on none
   of these, nor on the missing model.
3. **Other harnesses keep K33 as it is:** Amp, Codex and OpenCode still write the model.

## Supersedes

- .github/pull_request_template.md: "<claude | amp | codex | opencode>, <model id>" → "<claude | amp | codex | opencode>[, <model id>]"
