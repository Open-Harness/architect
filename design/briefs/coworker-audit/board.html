What Coworker is

A workspace where people give work to managers. A manager is a durable agent with a job, a mission page, a board, an email address and a way to ask a person. It hears from people and from outside, decides what is work, starts workers on tasks, and asks first when it must.

Three facts that shape everything

  • Two apps share the repository. An older chat app, and the manager product. Your screens page does not mention the older one. The rebuild is of the manager product.
  • Its own docs call the build a spike. They list 78 fixes found by using staging, none started. The redesign lives in three pages of docs.
  • Nested managers are not in the code. There is one level. A manager has no parent, and no manager knows of another.

What is worth keeping, by its own account

  • One place per workspace and one per manager, kept apart.
  • The vault: a key per workspace, used and never returned.
  • "Who may ask": the gate on what reaches a manager.
  • Email and GitHub in, with every awkward case tested.
  • A fake for every outside thing, picked in one file.
  • One list of actions for a person's buttons and a manager's tools.

Agents as actors

The Agent is already an actor in Orthograph, and the Pi conversation sits inside the same Durable Object. That is the design on main and the code in the draft. It is also where Coworker keeps a conversation today.

What an actor costs, from the canon:

  • It can't be listed. The compiler refuses. The answer it gives is "declare a view", and views are not built.
  • It can't hold a rule across records. So "one root manager per workspace" can't be a rule on the agent.
  • A request key on its operation dies. For telling an agent this is covered: the tell carries its own request id, and Pi takes it once.

So the lists come from rows the actors report to.

Managera row: name, job, the manager above, its agent
Runa row: its task, its manager, its last report, its agent
Agentan actor: the conversation, and nothing else

The sidebar's tree, search, "agents on this task" and the page of everything running all read the rows. When an agent starts a turn, goes idle or stops, an event updates its row. This is one more thing than "the manager is the actor", and it is the price of a list today.

Does Pi Durable fit "things last"?

Mostly, and well. A Pi conversation is a thing that lasts for years. Telling an agent is one short call. The turn runs inside the actor, and when it ends that is an event. Nothing is held open. It pulls against your call in four places.

A first blueprint

Thirty-two files for Coworker's core: manager, lane, task, run, ask, grant and page. It does not compile, and nobody has tried. An amber line is a blank: one only you can fill, or one the framework can't hold yet.

Three choices the sketch makes

  • An ask is a thing, not a sleeping tool call. The manager raises it and carries on. Your answer is its next turn.
  • An action is an operation. The list of 76 strings goes. What a manager may do is checked against the blueprint itself, so 46 actions with nothing behind them can't happen.
  • Pi keeps the conversation and nothing else. The board, the pages and the permissions move out of Pi's documents into things.

What is left out on purpose

  • Fifteen tables that exist for how the old code works: dedupe, fan-out, outboxes, routing, caches.
  • The whole older chat app.
  • The audit log as a table. Orthograph's own journal and traces already say who did what.
